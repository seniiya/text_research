# 간접화법 연구 — AI 응답 전략 분석

사용자가 ChatGPT와 나눈 실제 대화에서, AI 응답이 8가지 지원 전략(ESConv) 중
어디에 분량을 배분했는지 측정한다. 참여자의 사전·사후 감정 상태(SAM valence/arousal),
대화 목적, 그리고 AI 응답에 대한 불만 표시(pushback)와 함께 분석한다.

- 참여자 11명, ChatGPT 대화 11건 — 총 280 메시지 (Prompt 140 / Response 140)
- AI 응답 전략 라벨링 기준: [codebook_part1.md](codebook_part1.md) — ESConv 8전략
- 사용자 측 라벨링 기준: [codebook_part2.md](codebook_part2.md) — 대화 목적·소재·pushback
- 전략 분류 출처: Liu et al. (2021), *Towards Emotional Support Dialog Systems*, ACL 2021

## 연구자가 해야 할 것

### 1. 제1부 코딩 — AI 응답 전략

[codebook_part1.md](codebook_part1.md)를 기준으로 `data/coding/P01.xlsx` ~ `P11.xlsx`의

- 판정이 애매하면 코딩북 §6 우선순위를 위에서부터 적용한다.

## 코드 빠른 참조

코딩북을 열지 않고 확인하는 용도다. 판정 규칙과 경계 사례는 코딩북이 기준이다.

### 제1부 — ESConv 8전략 → `esconv` 열

출처: [codebook_part1.md](codebook_part1.md) §4. 상위 축은 §5.

| 코드 | 전략 | 정의 | 상위 축 |
|---|---|---|---|
| `QST` | 질문 | 사용자에게 정보나 감정을 되묻는 발화 | 탐색 |
| `RST` | 재진술 | 사용자가 한 말을 다시 정리해 되돌려 줌 | 탐색 |
| `RFL` | 감정 반영 | 사용자의 감정을 짚어 말해 줌 | 정서적 지원 |
| `SLF` | 자기개방 | 화자 자신의 경험·감정을 공유 | 정서적 지원 |
| `AFF` | 인정·안심 | 사용자를 긍정하거나 걱정을 덜어 줌 | 정서적 지원 |
| `SUG` | 제안 제시 | 구체적 행동·해결책 제안 | 도구적 지원 |
| `INF` | 정보 제공 | 사실·원인·수치 등 정보 전달 | 도구적 지원 |
| `OTH` | 기타 | 인사, 농담, 이모지, 목록 제목 등 | 기타 |

**판정 우선순위** (§6, 위에서부터 먼저 걸리는 규칙을 따른다)

1. 물음표로 끝나면 → `QST`
2. 사용자 말을 되돌려 정리하면 → `RST`
3. 감정어(힘들겠다, 이해돼, 답답하지)가 중심이면 → `RFL`
4. 걱정을 덜어 주거나 긍정하면 → `AFF`
5. "~해봐", "~하는 게 좋아" → `SUG`
6. 사실·원인·수치 설명 → `INF`
7. 위에 해당 없음 → `OTH`

> `OTH` 비율이 30%를 넘으면 분류 체계와 데이터가 맞지 않는다는 뜻이다 (§7).
> 그 경우 `OTH` 내용을 재검토하고 논문에 한계로 보고한다.

### 제2부 — 사용자 측 코드

출처: [codebook_part2.md](codebook_part2.md). 제1부와 코드 체계가 다르다.

**대화 목적** (에피소드 단위, §10) — 사전 설문 Q4 선택지를 그대로 사용

| 코드 | 목적 | 코드 | 목적 |
|---|---|---|---|
| `INFO` | 정보 검색·질문 | `ADV` | 고민 상담 → **조언** 요청 |
| `WORK` | 학업·업무 도움 | `ES` | 고민 상담 → **정서적 지지** 요청 |
| `WRITE` | 글쓰기 도움 | `PLAY` | 창작·놀이 |
| `CODE` | 코딩·기술 | `ETC` | 기타 |
| `CHAT` | 일상 잡담 | | |

`ADV`와 `ES`의 구분이 이 연구의 코딩 기여다. 설문의 "고민 상담" 하나를 둘로 쪼갠 것이다.
의문형·방법 요청이면 `ADV`, 서술형·감정 진술 중심이면 `ES` (§10 구분표 참고).

**소재** (에피소드 단위, §11) — 목적과 혼동하지 말 것.
목적은 "무엇을 원했나", 소재는 "무엇에 관한 이야기인가"다.

`HEALTH` 건강·신체 · `CAREER` 진로·학업 · `SOCIAL` 대인관계 · `FAMILY` 가족 ·
`JOB` 직무·감정노동 · `DAILY` 일상·취미 · `MONEY` 금전 · `ETC` 기타

**Pushback** (사용자 발화 단위, §12) — AI **응답 방식**에 대한 명시적 불만만 `Y`

| 코드 | 유형 |
|---|---|
| `VERBOSE` | 응답이 너무 길다 |
| `UNSOL_ADV` | 요청하지 않은 조언·해결책 |
| `CONTRA` | 사용자 진술을 반박·정정함 |
| `REPEAT` | 같은 말 반복 |
| `OTHER` | 그 외 불만 |

> 대화 **주제**에 대한 분노(학생·가족에 대한 짜증 등)는 pushback이 아니다.
> 연구자가 "답답해 보인다"고 추론한 것도 `Y`로 하지 않는다. 명시적으로 언어화된 것만이다.

## 데이터 재생성

원자료를 가진 사람만 실행할 수 있다. 공동연구자는 실행할 필요가 없다.

```bash
python scripts/deidentify.py                 # 원자료 → data/deid/
python scripts/make_coding_sheet.py P01      # → data/coding/P01.csv, P01.xlsx
```

`deidentify.py`는 마지막에 검증 단계를 돌려 `data/deid/` 전체를 훑고, 실명·URL·이메일·
전화번호가 하나라도 남아 있으면 비정상 종료한다.

분리 결과를 점검하려면 리포트를 찍는다 (파일은 만들지 않는다):

```bash
python scripts/split_sentences.py P01
```

> `make_coding_sheet.py`는 XLSX 생성에 openpyxl이 필요하다.
> 이 프로젝트에는 자체 venv가 없다. openpyxl이 설치된 인터프리터로 실행한다.

### 마크다운을 쓰는 이유

GPT는 한 문장을 여러 문단에 걸쳐 쓰는 일이 잦다. JSON 내보내기는 마크다운 구조를
버리기 때문에 문단마다 끊으면 문장이 조각난다.

```
'여기서는' / 'LLM을' / '"잘 만드는 것"' / '보다' / '"잘 사용하는 것"' / '이 중요하다.'
```

마크다운에는 리스트(`- `), 제목(`## `), 인용(`> `), 표(`| `) 표시가 남아 있어
**진짜 목록 항목과 끊긴 문단을 구분**할 수 있다. 끊긴 문단만 다시 이어 붙인다.

```
'여기서는 LLM을 "잘 만드는 것"보다 "잘 사용하는 것"이 중요하다.'
```

같은 사람의 `.md`와 `.json`이 둘 다 있으면 `.md`를 쓴다. 어느 쪽을 썼는지는
`data/deid/index.csv`의 `source` 열에 기록된다.

### 설문 CSV 구조 주의

설문 원본 한 파일에 표가 두 개 세로로 쌓여 있다. 스크립트가 이를 분리한다.

| 표 | 위치 | 내용 |
|---|---|---|
| A | 0행 헤더, 1~11행 | 접수 응답. 실명·share URL 포함 → 연결키 생성에만 사용 |
| B | `p_id` 헤더 행 이후 | 분석표. 이미 `P01`~`P11` 기준 → 그대로 공유 |

## 데이터 형식

### `data/coding/P##.csv` / `.xlsx`

| 열 | 값 |
|---|---|
| `p_id` | `P01` ~ `P11` |
| `turn` | 몇 번째 주고받기인지 (1부터) |
| `sent_no` | 해당 turn 안에서 몇 번째 문장인지. 문맥 행은 `-` |
| `role` | `Prompt`(사용자, 문맥) / `Response`(AI, 코딩 대상) |
| `text` | 문장 |
| `chars` | `text`의 글자 수 (공백 포함) |
| `esconv` | **입력란.** ESConv 8코드 중 하나. 문맥 행은 `-` |

XLSX에는 드롭다운·문맥 행 잠금·시트 보호가 걸려 있어 코딩 대상 셀에만 입력할 수 있다.
규칙을 바꿔야 하면 `[검토] → [시트 보호 해제]`로 푼다.

### `data/deid/chats/P##.json`

```json
{
  "metadata": {
    "title": "대화 제목",
    "user": { "name": "P04" },
    "dates": { "created": "...", "updated": "...", "exported": "..." },
    "format": "markdown"
  },
  "messages": [
    { "role": "Prompt",   "say": "사용자 발화", "time": "..." },
    { "role": "Response", "say": "AI 응답",    "time": "..." }
  ]
}
```

`format`이 `markdown`이면 `say`에 구조 표시가 살아 있고, `plain`이면 문단만 남아 있다.
코딩 대상은 `Response`뿐이다 (코딩북 제1부 §2).
