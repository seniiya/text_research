# 간접화법 연구 — AI 응답 전략 분석

> **연구 질문** — GPT는 어떤 지원 전략에 분량을 배분하며, 그것이 사용자의 감정 변화와
> 이탈에 어떻게 연결되는가.

참여자 **11명** · 대화 **11건** · 메시지 **280개** (사용자 140 / AI 140) · 에피소드 **15개**

---

## ⚠️ 먼저 읽을 것 — 개인정보

**이 저장소에 실명·연락처·공유 링크를 절대 올리지 않는다.** 참여자는 `P01`~`P11`로만 부른다.

| 경로 | 상태 | 내용 |
|---|---|---|
| `data/raw/` `data/survey/` `data/private/` | 🔒 **Git 제외** | 실명, ChatGPT 공개 share URL, 가명–실명 연결키 |
| `data/deid/` `data/coding/` | ✅ 공유 대상 | 가명화 완료 |

ChatGPT share URL은 **링크만 알면 누구나 열람**할 수 있다. 채팅에도 붙여넣지 않는다.

`deidentify.py`는 실행할 때마다 산출물 전체를 훑어 실명·URL·이메일·전화번호가
하나라도 남아 있으면 **비정상 종료**한다.

> **공동연구자에게** — 필요한 데이터는 전부 `data/deid/`와 `data/coding/`에 있다.
> 원자료가 필요하면 저장소가 아니라 연구책임자에게 요청한다.

참가자가 사후 설문에 직접 쓴 주제와 에피소드별 감정 점수. 9항 규칙 1도

**에피소드는 총 15개**다.

**설문으로 안 되는 것** (판정이 필요하다면 이 셋)

| 항목 | 왜 설문으로 안 되는가 |
|---|---|
| 턴 범위 | 설문은 주제 **이름**만 준다. 몇 번째 턴인지는 없다 |
| `ADV` / `ES` | 설문의 "고민 상담" 하나가 조언 요청과 정서 지지 요청을 안 나눈다 |
| 소재 | 설문에 해당 문항이 없다 |

> 턴 범위가 없으면 **에피소드별 전략 비율을 계산할 수 없다.**
> 설문의 에피소드별 자기보고 감정과 대화 로그를 잇는 유일한 고리다 (9항).

**Pushback은 실제로 드물다.** 사용자 발화 140개를 훑은 결과 12항 기준을 통과하는
후보는 4건이며, 그중 3건이 응답 길이 문제였다. 전수 판정이 필요한지, 양성 사례만
기록해도 되는지는 제1부를 끝낸 뒤 정한다.

## 📋 코드 빠른 참조

코딩북을 열지 않고 확인하는 용도다. **판정 규칙과 경계 사례는 코딩북이 기준이다.**

### 제1부 — ESConv 8전략 → `esconv` 열

<table>
<tr><th>축</th><th>코드</th><th>전략</th><th>정의</th></tr>
<tr><td rowspan="3"><b>정서적<br>지원</b></td>
    <td><code>RFL</code></td><td>감정 반영</td><td>사용자의 감정을 짚어 말해 줌</td></tr>
<tr><td><code>AFF</code></td><td>인정·안심</td><td>사용자를 긍정하거나 걱정을 덜어 줌</td></tr>
<tr><td><code>SLF</code></td><td>자기개방</td><td>화자 자신의 경험·감정을 공유</td></tr>
<tr><td rowspan="2"><b>도구적<br>지원</b></td>
    <td><code>SUG</code></td><td>제안 제시</td><td>구체적 행동·해결책 제안</td></tr>
<tr><td><code>INF</code></td><td>정보 제공</td><td>사실·원인·수치 등 정보 전달</td></tr>
<tr><td rowspan="2"><b>탐색</b></td>
    <td><code>QST</code></td><td>질문</td><td>사용자에게 정보나 감정을 되묻는 발화</td></tr>
<tr><td><code>RST</code></td><td>재진술</td><td>사용자가 한 말을 다시 정리해 되돌려 줌</td></tr>
<tr><td><b>기타</b></td><td><code>OTH</code></td><td>기타</td><td>인사, 농담, 이모지, 목록 제목 등</td></tr>
</table>

**판정 우선순위** — 위에서부터 먼저 걸리는 규칙을 따른다 (6항)

```
1. 물음표로 끝난다                        → QST
2. 사용자 말을 되돌려 정리한다              → RST
3. 감정어(힘들겠다·이해돼·답답하지)가 중심   → RFL
4. 걱정을 덜어 주거나 긍정한다              → AFF
5. "~해봐", "~하는 게 좋아"                → SUG
6. 사실·원인·수치를 설명한다                → INF
7. 위에 해당 없음                          → OTH
```

> ⚠️ **`OTH`가 30%를 넘으면** 분류 체계가 데이터에 맞지 않는다는 뜻이다 (7항).
> `OTH` 내용을 재검토하고 논문에 한계로 보고한다.

<details>
<summary><b>제2부 — 사용자 측 코드</b> (대화 목적 · 소재 · pushback)</summary>

제1부와 코드 체계가 다르다. 출처: [코딩북 제2부](codebook_part2.md)

**대화 목적** — 에피소드 단위 (10항). 사전 설문 Q4 선택지를 그대로 사용

| 코드 | 목적 | 코드 | 목적 |
|---|---|---|---|
| `INFO` | 정보 검색·질문 | `ADV` | 고민 상담 → **조언** 요청 |
| `WORK` | 학업·업무 도움 | `ES` | 고민 상담 → **정서적 지지** 요청 |
| `WRITE` | 글쓰기 도움 | `PLAY` | 창작·놀이 |
| `CODE` | 코딩·기술 | `ETC` | 기타 |
| `CHAT` | 일상 잡담 | | |

> **`ADV` vs `ES` 구분이 이 연구의 코딩 기여다.** 설문의 "고민 상담" 하나를 둘로 쪼갠 것.
> 의문형·방법 요청이면 `ADV`, 서술형·감정 진술 중심이면 `ES`.

**소재** — 에피소드 단위 (11항). 목적은 "무엇을 원했나", 소재는 "무엇에 관한 이야기인가"

`HEALTH` 건강·신체 · `CAREER` 진로·학업 · `SOCIAL` 대인관계 · `FAMILY` 가족
`JOB` 직무·감정노동 · `DAILY` 일상·취미 · `MONEY` 금전 · `ETC` 기타

**Pushback** — 사용자 발화 단위 (12항). AI **응답 방식**에 대한 명시적 불만만 `Y`

| 코드 | 유형 |
|---|---|
| `VERBOSE` | 응답이 너무 길다 |
| `UNSOL_ADV` | 요청하지 않은 조언·해결책 |
| `CONTRA` | 사용자 진술을 반박·정정함 |
| `REPEAT` | 같은 말 반복 |
| `OTHER` | 그 외 불만 |

> ⚠️ 대화 **주제**에 대한 분노(학생·가족에 대한 짜증)는 pushback이 **아니다**.
> 연구자가 "답답해 보인다"고 추론한 것도 `Y`로 하지 않는다. **명시적으로 언어화된 것만**이다.

</details>

### 마크다운을 쓰는 이유

GPT는 **한 문장을 여러 문단에 걸쳐 쓰는 일이 잦다.** JSON 내보내기는 마크다운 구조를
버리기 때문에 문단마다 끊으면 문장이 조각난다.

```
'여기서는' / 'LLM을' / '"잘 만드는 것"' / '보다' / '"잘 사용하는 것"' / '이 중요하다.'
```

마크다운에는 리스트(`- `), 제목(`## `), 인용(`> `), 표(`| `) 표시가 남아 있어
**진짜 목록 항목과 끊긴 문단을 구분**할 수 있다. 끊긴 문단만 다시 이어 붙인다.

```
'여기서는 LLM을 "잘 만드는 것"보다 "잘 사용하는 것"이 중요하다.'
```

같은 사람의 `.md`와 `.json`이 둘 다 있으면 `.md`를 쓴다. 어느 쪽을 썼는지는
`data/deid/index.csv`의 `source` 열에 기록된다.

### 설문 CSV 구조 주의

설문 원본 한 파일에 표가 **두 개 세로로 쌓여** 있다. 스크립트가 이를 분리한다.

| 표 | 위치 | 내용 |
|---|---|---|
| A | 0행 헤더, 1~11행 | 접수 응답. 실명·share URL 포함 → **연결키 생성에만** 사용 |
| B | `p_id` 헤더 행 이후 | 분석표. 이미 `P01`~`P11` 기준 → 그대로 공유 |

</details>
