# 관찰 기록

코딩 시트의 `note` 열은 **행 단위**라 여러 턴에 걸친 관찰이 안 들어간다.
그런 관찰을 여기에 모은다.

## 쓰는 법

관찰 하나에 항목 하나. 번호는 `OBS-###`로 이어 붙이고 재사용하지 않는다.

```markdown
## OBS-000 · 한 줄 제목
- 참여자/구간 :
- 관찰       : 무엇을 봤는가
- 근거       : 수치·인용. 재현 명령이 있으면 같이
- 가설       : 이 관찰이 참이라면 무엇이 따라오는가
- 반증       : 어긋나는 사례. 없으면 "확인 안 함"
- 등급       : 사례(n=1) / 복수사례(n≥3) / 전수
- 상태       : 미검증 / 검증중 / 확정 / 기각
```

**`등급`과 `상태`를 반드시 적는다.** 나중에 논문을 쓸 때 n=1 관찰을 설계 명세로
올려 쓰는 사고를 막아 준다. 사례는 가설의 근거는 되지만 주장의 근거는 안 된다.

인용은 `data/deid/chats/` 의 가명화된 로그에서만 가져온다. 원자료를 붙이지 않는다.

## OBS-001 · AI가 응답 말미에 정보를 요구하면 사용자가 거부하거나 이탈한다

- **참여자/구간** : P01 turn 1~11, P03 turn 2, P04 turn 4
- **관찰**

  세 대화에서 같은 구조가 반복된다. AI가 긴 응답 끝에 사용자에게 정보를
  요구하며 턴을 넘기고, 사용자가 바로 다음 턴에서 거부한다.

  | | 직전 AI 응답 말미 | 사용자 반응 |
  |---|---|---|
  | P01 t3 | "키 / 현재 체중 / 최근 3개월 전 체중이 어떻게 되는지 말해주면…" (684자) | "하 왤케 이것저것 시키려고 하는 거니. 나의 신체적 비밀까지 알려고 하지마" |
  | P03 t2 | "요즘 스트레스는 어떤 쪽이 제일 커?" + 5지선다 (820자) | "너무 길게 답하진 말아줘" |
  | P04 t4 | "종목명만 보내줘. 같이 살펴보자." (425자) | "됐다 안할래" |

  P01은 **감정 개방에 대한 응답**으로 신체 수치를 요구받았다는 점에서 특히 뚜렷하다.
  turn 1의 개방이 "요즘 잘 움직이지도 않고 배가 자꾸 나오는 거 같아서 너무 걱정이야"
  였는데, 돌아온 것이 측정값 요구였다. **개방의 축과 요구의 축이 어긋난다.**

- **근거**

  ```
  P01 사용자 발화 길이  [37, 56, 41, 13, 64, 17, 17, 9, 22, 8, 50]
    거부(t3) 이전 평균 46자  ->  이후 평균 27자
    t9  "너라면 키몸무게 이런거 밝힐 수 있겠냐?"   <- 6턴 뒤까지 남아 있음
    t10 "훈수 그만 둬."
    t11 "이럼 나는 그냥 친구들한테 뱃살 고민 상담 받지"   <- 대체 선언

  QST 비율 (응답 단위)   P01 18~27%,  P06 33%
  QST 비율 (문장 단위)   P01 1.1~3.2%, P06 1.6%
  ```

  재현: `python scripts/agreement.py P01` / `P06`

  **분모를 문장으로 두면 안 보인다.** 30문장짜리 응답에 질문 1개면 3%다.
  사용자가 체감하는 것은 응답 단위 빈도이고, 그쪽은 3~4개 중 1개꼴이다.

- **가설**

  1. 요구형 질문이 감정 개방을 억제한다.
  2. `QST`를 "질문"으로만 세면 이 효과가 안 보인다. **무엇을 요구하는 질문인가**를
     나눠야 보인다 (정보 요구 / 감정 탐색).

- **반증**

  **P04는 회복한다.** turn 4에서 "됐다 안할래"로 끊었지만 이후 발화가
  42 → 47 → 63자로 오히려 늘어난다. 거부가 곧 이탈은 아니다.

  세 사례 모두 거부 직후 **AI 응답이 급격히 짧아진다** (166자 / 191자 / 216자).
  AI가 적응하기 때문에, 억제가 지속되는지 회복되는지는 사례마다 갈린다.

  따라서 지금 말할 수 있는 것은 **"정보 요구가 거부를 유발한다"**까지이고,
  **"감정 개방을 억제한다"**는 아직 확인되지 않았다.

- **등급** : 복수사례 (n=3)
- **상태** : 미검증

### 후속으로 할 것

- [ ] `QST` 비율을 **응답 단위**로 보고한다. 문장 단위는 과소 추정이다.
- [ ] `QST` 하위 태그(정보 요구 / 감정 탐색)는 **`OTH` 경계를 정한 뒤에** 검토한다.
      지금 축을 더하면 일치도가 더 떨어진다.
- [ ] 거부 이후 개방량이 회복되는 경우와 안 되는 경우를 가르는 것이 무엇인지 확인.
      현재 P01(회복 안 함) vs P04(회복함) 두 사례뿐이다.

## 검토 대기 — 자동 탐지된 후보

사용자 발화에서 응답 방식에 대한 불만·차단 신호를 찾은 결과다.
**아직 읽어 보지 않은 것들이므로 관찰이 아니라 후보다.**

| 참여자 | turn | 직전 AI | 사용자 발화 | 메모 |
|---|---|---|---|---|
| P01 | 3, 10, 11 | 684 / 489 / 216자 | 위 OBS-001 | 반영 완료 |
| P03 | 2, 8 | 820 / 404자 | "너무 길게 답하진 말아줘" · "길게 답장은 하지 마" | **같은 불만 2회.** 응답 길이 불만 전용 사례 |
| P04 | 4, 13 | 425 / 519자 | "됐다 안할래" · "그정도면 그냥 포기를 하지 싶음" | 반영 완료(t4). t13 미확인 |
| P02 | 4 | 1650자 | 로봇/산업 지식 부족을 토로 | 불만인지 자기개방인지 애매 |
| P11 | 6 | 644자 | "운동이 귀찮은 타입" | **오탐.** 자기 서술이지 불만 아님 |

재현: 아래로 다시 뽑을 수 있다.

```bash
python - <<'PY'
import json,re
from pathlib import Path
PUSH=re.compile(r'그만|하지\s?마|알려고|됐다|됐어|안할래|귀찮|길게|짧게|간단히|로봇|잔소리|훈수|시키려|캐묻|필요없')
for f in sorted(Path('data/deid/chats').glob('*.json')):
    d=json.loads(f.read_text(encoding='utf-8')); t=0
    for i,m in enumerate(d['messages']):
        if m['role']!='Prompt': continue
        t+=1
        if PUSH.search(m['say']):
            prev=d['messages'][i-1]['say'] if i else ''
            print(f.stem, f'turn {t}', f'직전AI {len(prev)}자', m['say'][:50].replace('\n',' '))
PY
```

> 이 정규식은 **후보를 놓치기도 하고 오탐도 낸다** (P11이 그 예). 최종 판정은
> 코딩북 12항 기준으로 사람이 한다. 자동 탐지는 읽을 곳을 좁히는 용도다.
