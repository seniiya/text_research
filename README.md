### 1. 제1부 코딩 — AI 응답 전략 `2인 코딩 대기`

`data/coding/<코더>/P##.xlsx`의 **`esconv` 열**을 채운다. → 기준: [코딩북 제1부](codebook_part1.md)

시트는 20명분(`P01`~`P20`) 다 만들어져 있다. 코딩 대상은 총 9,360행.

| 코더 | `P01` | `P06` | 그 외 |
|---|---|---|---|
| coder1 | 183건 완료 | 123건 완료 | 대기 |
| coder2 | 185건 완료 | **다음 차례** | 대기 |

**다음 할 일은 `coder2`의 `P06`이다.** 이게 끝나야 신뢰도를 낼 수 있는 첫 쌍이 나온다.

> ⚠️ **`P01`의 일치도는 보고할 수 없다.** coder1이 `P01` 참여자 본인이다. 본인은
> 자기가 그때 뭘 원했는지 알기 때문에, 텍스트만 보고 판정해야 하는
> `RST`·`RFL`·`QST`가 독립적인 판정이 아니다. 연구자가 2명뿐이라 다른 조합을
> 만들 수도 없다.
>
> 양쪽 라벨 368건(coder1 183 + coder2 185)은 **신뢰도 근거로 쓰지 않는다.**
> 다만 불일치 패턴은 코딩북을 고치는 데 그대로 쓸 수 있다 (아래).

**유효한 파일럿 쌍은 `P06`(124행) + `P03`(142행)이다.** 둘 다 고민 상담 성격이라
정서적 지원 코드가 실제로 나오고, 어느 코더도 본인이 아니다.

#### `P01` 참고 수치와 거기서 드러난 문제

`python scripts/agreement.py P01` → **κ = 0.423** (Po 0.536, 183행 기준).
보고용은 아니지만 코딩북의 구멍은 그대로 보여 준다.

| 문제 | 근거 |
|---|---|
| **`OTH` 판정이 갈린다** | coder1 55건 vs coder2 19건. 코드별 κ 0.297. 전체 불일치 85건 중 34건이 coder1의 `OTH`와 얽혀 있다 |
| **`RST`이 사실상 안 맞는다** | coder1 8 vs coder2 13인데 일치 1건. κ 0.043 |
| **`SLF`은 우연 이하** | κ −0.009. GPT는 자기 경험을 공유할 수 없는데 coder2가 6건 매겼다 |

`OTH`가 핵심이다. 코딩북이 `OTH`에 "목록 제목"을 넣어 둬서, coder1은 짧은 구·
제목을 `OTH`로 보내고 coder2는 내용 코드를 준다 (`당장 추천하는 것` → `OTH`/`SUG`,
`훈수 종료.` → `OTH`/`RST`). **`P06`을 코딩하기 전에 이 경계를 먼저 정해야 한다.**

- 회색 행(`role = Prompt`)은 **사용자 발화**다. 잠겨 있고 코딩 대상이 아니다.
  `RST`·`RFL`·`QST`는 사용자가 뭐라고 했는지 봐야 판정되기 때문에 넣어 둔 것이다.
- 애매하면 **판정 우선순위**(아래 참조)를 위에서부터 적용하고, 이유를 `note`에 적는다.

> ⚠️ **coder2 는 coder1 폴더를 열지 않는다.** 코딩북 제2부 15항이 "서로의 결과를
> 보지 않는다"를 요구한다. 파일 2개와 코딩북만 전달받는 편이 안전하다.
>
> **코더가 참여자 본인인 파일도 열지 않는다.** 위 `P01` 건이 그렇게 생겼다.
> 누가 어느 `P##`인지는 `data/private/mapping.csv`에만 있다.

참가자가 사후 설문에 직접 쓴 주제와 에피소드별 감정 점수. 9항 규칙 1도

| 항목 | 왜 설문으로 안 되는가 |
|---|---|
| 턴 범위 | 설문은 주제 **이름**만 준다. 몇 번째 턴인지는 없다 |

> 설문의 에피소드별 자기보고 감정과 대화 로그를 잇는 유일한 고리다 (9항).

### 3. 데이터 정비 `완료`

**대화 20건이 모두 마크다운 기반**이다. 평문으로만 있던 8명분을 `.md`로 다시
내보내 정리를 끝냈다. 이제 같은 GPT 텍스트가 참여자마다 다르게 쪼개지지 않으므로,
**참여자 간 분량 비교가 가능하다.**

`python scripts/deidentify.py`가 실행할 때마다 평문으로 남은 참여자를 경고로 알려준다.
지금은 아무도 걸리지 않는다.

### 4. 확인 필요

- **`후_A`가 `P12`·`P13`·`P14`에서 비어 있다.** 2차 폼 첫날 3명인데, 그 시점에
  폼에 사후 arousal 문항이 없었다. 응답자 탓이 아니라 도구 결측이다.
  **제외하지 않는다** — 결측이 참여자의 상태와 무관하므로, arousal 분석에서만
  `n=17`로 빼고 나머지 분석에는 전원 포함한다.
- **`OTH` 경계를 정해야 한다.** `P01`에서 coder1 30%(55/183) vs coder2 10%(19/183).
  7항 진단선이 30%인데, 이게 데이터 문제인지 판정 기준 문제인지 갈린다.
- `SLF`는 GPT가 자기 경험을 공유할 수 없어 구조적으로 관찰되기 어렵다. ESConv
  원 데이터에서는 약 9.7%를 차지하는 전략이다. `P01`에서 coder2가 6건 매긴 것을
  조정 회의에서 확인해야 한다.

**판정 우선순위** — 위에서부터 먼저 걸리는 규칙을 따른다 (6항)

```
1. 물음표로 끝난다                        → QST
2. 사용자 말을 되돌려 정리한다              → RST
3. 감정어(힘들겠다·이해돼·답답하지)가 중심   → RFL
4. 걱정을 덜어 주거나 긍정한다              → AFF
5. "~해봐", "~하는 게 좋아"                → SUG
6. 사실·원인·수치를 설명한다                → INF
7. 위에 해당 없음                          → OTH
```

> ⚠️ **`OTH`가 30%를 넘으면** 분류 체계가 데이터에 맞지 않는다는 뜻이다 (7항).
> `OTH` 내용을 재검토하고 논문에 한계로 보고한다.

<summary><b>제2부 — 사용자 측 코드</b> (대화 목적 · 소재 · pushback)</summary>

제1부와 코드 체계가 다르다. 출처: [코딩북 제2부](codebook_part2.md)

**대화 목적** — 에피소드 단위 (10항). 사전 설문 Q4 선택지를 그대로 사용

| 코드 | 목적 | 코드 | 목적 |
|---|---|---|---|
| `INFO` | 정보 검색·질문 | `ADV` | 고민 상담 → **조언** 요청 |
| `WORK` | 학업·업무 도움 | `ES` | 고민 상담 → **정서적 지지** 요청 |
| `WRITE` | 글쓰기 도움 | `PLAY` | 창작·놀이 |
| `CODE` | 코딩·기술 | `ETC` | 기타 |
| `CHAT` | 일상 잡담 | | |

> **`ADV` vs `ES` 구분이 이 연구의 코딩 기여다.** 설문의 "고민 상담" 하나를 둘로 쪼갠 것.
> 의문형·방법 요청이면 `ADV`, 서술형·감정 진술 중심이면 `ES`.

**소재** — 에피소드 단위 (11항). 목적은 "무엇을 원했나", 소재는 "무엇에 관한 이야기인가"

`HEALTH` 건강·신체 · `CAREER` 진로·학업 · `SOCIAL` 대인관계 · `FAMILY` 가족
`JOB` 직무·감정노동 · `DAILY` 일상·취미 · `MONEY` 금전 · `ETC` 기타

**Pushback** — 사용자 발화 단위 (12항). AI **응답 방식**에 대한 명시적 불만만 `Y`

| 코드 | 유형 |
|---|---|
| `VERBOSE` | 응답이 너무 길다 |
| `UNSOL_ADV` | 요청하지 않은 조언·해결책 |
| `CONTRA` | 사용자 진술을 반박·정정함 |
| `REPEAT` | 같은 말 반복 |
| `OTHER` | 그 외 불만 |

> ⚠️ 대화 **주제**에 대한 분노(학생·가족에 대한 짜증)는 pushback이 **아니다**.
> 연구자가 "답답해 보인다"고 추론한 것도 `Y`로 하지 않는다. **명시적으로 언어화된 것만**이다.

</details>

```json
    { "role": "Response", "say": "AI 응답",    "time": "…" }
  ]
}
```

`format`이 `markdown`이면 `say`에 구조 표시가 살아 있고, `plain`이면 문단만 남아 있다.
**현재 20건 모두 `markdown`이다.** 코딩 대상은 `Response`뿐이다 (제1부 2항).

대화 본문에 참여자 실명이 남아 있으면 `deidentify.py`가 `[이름]`으로 바꾼다.
GPT가 성을 뗀 이름으로 부르는 일이 잦아서(`"○○이는 22살이지만"`) 풀네임만으로는
걸러지지 않는다.

### 마크다운을 쓰는 이유

GPT는 **한 문장을 여러 문단에 걸쳐 쓰는 일이 잦다.** JSON 내보내기는 마크다운 구조를
버리기 때문에 문단마다 끊으면 문장이 조각난다.

```
'여기서는' / 'LLM을' / '"잘 만드는 것"' / '보다' / '"잘 사용하는 것"' / '이 중요하다.'
```

마크다운에는 리스트(`- `), 제목(`## `), 인용(`> `), 표(`| `) 표시가 남아 있어
**진짜 목록 항목과 끊긴 문단을 구분**할 수 있다. 끊긴 문단만 다시 이어 붙인다.

```
'여기서는 LLM을 "잘 만드는 것"보다 "잘 사용하는 것"이 중요하다.'
```

같은 사람의 `.md`와 `.json`이 둘 다 있으면 `.md`를 쓴다. 어느 쪽을 썼는지는
`data/deid/index.csv`의 `source` 열에 기록된다.

### 설문 CSV 구조 주의

설문 원본이 **두 벌**이다. 1차 폼은 한 파일에 표가 두 개 세로로 쌓여 있고,
2차 모집은 폼을 새로 만들어 열 구성이 다르다. 스크립트가 둘을 합쳐 하나의
분석표로 만든다.

| 출처 | 위치 | 내용 |
|---|---|---|
| 1차 표 A | 0행 헤더, 1~11행 | 접수 응답. 실명·share URL 포함 → **연결키 생성에만** 사용 |
| 1차 표 B | `p_id` 헤더 행 이후 | 분석표. 이미 `P01`~`P11` 기준 → 그대로 공유 |
| 2차 폼 | 별도 CSV, 헤더 1줄 | 접수 순서대로 `P12`부터 부여. 열 이름을 표 B에 맞춰 변환 |

설문 응답을 연구자가 바로잡은 내역은 **`deidentify.py`의 `CORRECTIONS`에만** 적는다.
`survey_analysis.csv`를 직접 고치면 다음 실행에서 덮어써진다 — 스크립트가 이 파일을
매번 통째로 다시 만들기 때문이다. 손으로 고친 값이 발견되면 실행 중 경고가 뜬다.
